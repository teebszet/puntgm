# puntgm.com — the free board

Static site, generated by `scripts/build_site.py`. No framework and no backend: the board is
156 players across 9 punt builds, which fits in one payload and sorts client side.

```
FANTASY_GM_DATA_DIR=/path/to/data python scripts/build_site.py --as-of 2026-08-24 --out site/dist
```

Three pages, and the split between them is deliberate:

| page | what it is |
|---|---|
| `index.html` | the board — the artifact |
| `evidence.html` | the replay numbers, including the comparison we lose |
| `method.html` | how it is measured, and the two errors we found in our own numbers |

## The one rule for this directory

**Everything published here is generated from `build_board`** — the same function the replay
harness grades. Not a copy of its output, the same call. That is what makes "the track record is
the content" a true statement rather than a slogan, and it is why the board's `basis` provenance
line is rendered on two of the three pages and cannot be dropped by the template.

If a number on this site cannot be reproduced by running the package, it should not be here.

## Deploying

The build needs the SQLite store, which is not in the repository (26k+ game logs). So CI cannot
currently regenerate the board from scratch — `site/dist` is built locally and deployed. Making
the store reproducible from `nba_api` in CI is the obvious follow-up, and until it exists the
deploy is a manual step with a human looking at the board first. Given the top-30 is the entire
product surface, that review is worth keeping even once it could be automated.
