# Web tools (puntgm.com/tools)

The web surface of the Co-GM: decision boards served from a read-only snapshot of
the fantasy store, behind a Yahoo OAuth gate. The boards show uncertainty (σ,
25–75% bands) instead of bare point projections — the daily digest posts were
retired 2026-11-24 in favor of this surface.

## What's on the page

- **Wire-lines board** (`/api/tools/wire-lines`) — today's stat-line watch: every
  player who crossed a stated threshold (pts > 20, ast > 5, reb > 9, stl > 2,
  blk > 2 — strictly), with his full line, usage-table minutes, and games left
  (OUT → 0). Players who landed exactly on a threshold are listed as near-misses.
  Ties order pts, reb, ast, stl, blk descending, then player_id.
- **Fixture grid** (`/api/tools/fixture-grid`) — a 14-day team×team grid of
  defensive favorability: volume-weighted allowed rates per category
  (previous-season fallback under 5 team-games), direction-aware favorability
  with ranks, and (defense, G/F/C) position cells.
- **Matchup table** (`/api/tools/matchup`) — the live week: per-category
  projections with σ and 25–75% bands, and games-remaining per team (per-day
  scheduled starters whose team plays; bench/IL never count; verified against
  Yahoo's counter).
- **Schedule grid** (`/api/tools/schedule-grid`) — Hashtag-style NBA teams ×
  next-14-days matrix: one cell per scheduled game (`vs`/`@` + opponent),
  tinted by opponent-defense favorability averaged across all categories
  (per-category ×values in the hover), with a league slate-per-day row. Built
  from the same defense model and schedule dedupe as the fixture grid.
- **Scoreboard** (`/api/tools/scoreboard`) — Elvin-Feng-style weekly matchup
  comparisons: every active matchup in the league, both teams' projected
  end-of-week totals per category with σ and 25–75% bands, per-category win
  probability, games-remaining, and a projected score counting categories led.
  One Projector call per matchup; a team appears exactly once.
- **Teams** (`/api/tools/teams`) — roster payloads behind the same gate.

The static shell (`site/dist/tools/index.html`) is generated by
`scripts/build_tools.py`; every number arrives from the API. Nothing on the page
is hand-placed.

## Auth

Yahoo OAuth, identity only. Sessions are an HMAC-signed cookie (30 days); the
guid allow-list (`YAHOO_ALLOWED_GUID`) restricts access to Tim's account. Every
`/api/tools/*` route denies without a session (401 — an anonymous tools payload
is a leak). `/api/health` is public and reports `auth_ready`.

## Environment variables

| Var | Purpose |
|-----|---------|
| `SESSION_SECRET` | HMAC key for the session cookie |
| `YAHOO_CLIENT_ID` / `YAHOO_CLIENT_SECRET` | Yahoo OAuth app credentials |
| `YAHOO_REDIRECT_URI` | OAuth callback URL |
| `YAHOO_ALLOWED_GUID` | Yahoo guid allowed to sign in |
| `FANTASY_GM_STORE` | Path to the bundled snapshot (default `api/store/snapshot.sqlite`) |
| `TOOLS_LEAGUE_ID` / `TOOLS_TEAM_ID` | League/team the boards are scoped to |
| `TOOLS_TEAM_BY_GUID` | Optional `guid:team_id` pairs (comma-separated): each signed-in account's own team for the matchup/fixture-grid boards; unmapped guids fall back to `TOOLS_TEAM_ID` |

## Running the API locally

```bash
FANTASY_GM_STORE=data/fantasy_gm.sqlite \
SESSION_SECRET=... YAHOO_CLIENT_ID=... YAHOO_CLIENT_SECRET=... \
YAHOO_REDIRECT_URI=... YAHOO_ALLOWED_GUID=... \
uvicorn api.index:app
```

Without the Yahoo vars the app still serves the static site and 401s the tools
routes (`auth_ready=false`).

## Deploy model (process of record)

- **Push to `main` = production deploy** (Vercel GitHub integration). Branches
  deploy auth-protected previews.
- The Vercel function is self-contained: it imports a **vendored copy** of
  `fantasy_gm` (`api/fantasy_gm/`) and reads a **bundled snapshot**
  (`api/store/snapshot.sqlite`), both committed in-repo. `vercel.json` carries
  `includeFiles: "**"` — a single string glob; an array fails config validation.
- The committed `site/dist` board is the **board of record**. A rebuild at the
  same `as_of` still shifts every z-score (league-rate/usage drift under the
  fixed date), so re-base only through the explicit rebuild flow — never by
  silently regenerating the committed board.
- **Daily data**: the 14:30 HKT launchd wrapper refreshes the wires, then
  `~/.buzz/scripts/puntgm_daily_snapshot.sh` commits a fresh snapshot to main
  (idempotent no-op when unchanged). It converges the `fnba-webtools-main`
  worktree to origin/main first.
- `scripts/deploy_webtools.py` (Vercel CLI deploys) is **legacy**.

## Store vs Yahoo

The snapshot is the store's read of Yahoo data and is the basis of record for
the boards. Known drift (the transaction-ingest gap — roster moves fetched but
never stored, so wire moves can mis-attribute by up to a day of games) is
tracked in the fantasy-nba-gm channel; Yahoo's scoreboard API is the
ground-truth check.
